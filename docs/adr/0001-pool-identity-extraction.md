# ADR 0001：简历入池即提取身份信息，粘贴录入按身份查重

日期：2026-09-15
状态：已接受

## 背景

新增「粘贴文本录入简历」功能时需要决定去重方式。现有文件简历按 `(job_id, sha256)` 内容哈希去重，但纯文本简历从不同渠道复制会得到空白/换行不同的文本，内容哈希会漏判；且池简历 `job_id` 为空，唯一约束本来就不生效（邮箱捕获已是应用层查重）。

## 决策

1. 简历入池（邮箱捕获、粘贴录入）即异步调用文本模型提取结构化身份信息（姓名/邮箱/手机号），邮箱手机号以正则兜底校验，结果存在 `resumes` 表新列。
2. 粘贴录入时按身份信息查重：命中池内已有简历则提醒并展示疑似重复项，用户确认后才录入；未命中直接录入。漏网的重复由人工事后删除或合并，系统不做模糊/相似度去重。
3. 提取范围仅限入池简历；直接上传到岗位的简历不提取。

## 备选方案

- **内容哈希（规范化后 sha256）**：实现简单，但换行/空白差异即失效，且无法回答"这个人是否已经在池里"。
- **粘贴时临时对全库 `parsed_text` 做文本扫描**：无需新字段，但每次粘贴都扫全库，且结果不可复用、不可展示。
- **粘贴时同步调模型提取**：粘贴操作需等待模型返回，交互变慢；异步提取 + 正则即时查重足够覆盖提醒场景。

## 后果

- 需要一次 Alembic 迁移与存量池简历回填（统一走 `pending` 队列，无一次性脚本）。
- 每份入池简历增加一次模型调用成本；失败可重试，不阻塞入池。
- 查重质量依赖身份提取质量；姓名仅作辅助信号，重名误报可接受。
